# Itera Agent Manifests

Public store for the configuration files ("manifest") of coding agents submitted by Itera
Agent Proof users for benchmark evaluation. Each agent is defined by its own convention files
(`CLAUDE.md`, `AGENTS.md`, `skills/`, `context/`) — not a live HTTPS endpoint.

## Layout

```
agents/
  <user_uuid>/
    <model-slug>/
      CLAUDE.md            # any subset of these, whatever the client's agent uses
      AGENTS.md
      skills/
      context/
      _manifest.json       # generated by the platform on submit — do not hand-edit
```

- `<user_uuid>` — the user's id as registered on the Itera platform.
- `<model-slug>` — the model the user declares for this agent (e.g. `claude-sonnet`,
  `qwen2.5-coder`, `deepseek-coder`, `gemini`). One folder per (user, model) pair.
- `_manifest.json` — written by the Itera platform on every submit/resubmit: declared model, CLI
  (`opencode` or `raw_openrouter`), file list, submission timestamp, and the commit SHA of that
  version. Resubmitting overwrites the folder's content and bumps `_manifest.json.version`; prior
  versions remain recoverable from this repo's git history.

## How a run references a manifest

The Itera evaluator pins the exact `commit_sha` of the manifest version it evaluated
(`public.agent_manifest_versions.commit_sha` in the Itera database) — so a result is always
traceable to the exact agent configuration that produced it, even after the user updates their
agent later.

Part of the [Itera Agent Proof](https://github.com/devfellowship/itera-certificacao-onchain)
project (Colosseum Crypto World's Fair hackathon).
